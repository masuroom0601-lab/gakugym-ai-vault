## ミッション
AIが描く漫画を、できるだけ「人間が描いたような」作風で制作する。
作品の中身(ジャンル・テーマ・用途)は益田さんの指示で決める。

## 基本方針
- **完全無料で作る**。Claude Code Proの契約の範囲内で完結させ、有料の画像生成サービス
  (Higgsfield等)や有料素材は使わない。
- **描くのはAI**。益田さんの作業は、方向性の指示・参考イラストの提供・最終確認に限る。
- **公開前には必ず益田さんが確認する**(全部署共通ルール)。

## 制作方式
### 画像生成AI(2026-11-21追加、作画の主力)
- Hugging Faceで無料公開されているSpace「Asahina2K/animagine-xl-4.0」(アニメ絵の
  画像生成AI Animagine XL 4.0)を、`tools/generate_hf.py`から呼び出す。
- 益田さんの無料アカウントの鍵(Readトークン)を、クラウド環境のネットワーク設定に
  保存済み(huggingface.co と asahina2k-animagine-xl-4-0.hf.space の2か所)。
  鍵はファイルやチャットに書かない。
- 無料枠(ZeroGPU)には1日あたりの上限がある。上限に達したら翌日に回す。
- Gemini API(Google AI Studioの無料の鍵)も試したが、無料枠では画像生成の上限が0で
  使えなかった(2026-11-21確認。Gemini Plusの加入はAPIの枠に影響しない)。
- 公開・販売の前に、Animagine XL 4.0のライセンス条件を確認すること。
- **見本画像からの描き分け**(2026-11-21追加): 文章だけでは服装などが毎回変わるため、
  基準画(`characters/shiina/test_hf_v2a.png`)を見本として渡し、同じキャラを別のポーズ・
  表情で描かせる。Hugging Faceの無料Space「Qwen-Image-Edit」(Apache 2.0、商用可)を
  `tools/edit_qwen.py`から使う(高速版が標準、`--full`で公式版)。鍵は2つのSpaceにも保存済み。
  FLUX.1 Kontextは非商用ライセンスのため使わない。
- これでも見た目がそろわない場合は、椎菜専用の追加学習(LoRA)に進む(益田さん承認済み)。

### Blender(ポーズ・構図の下絵用)
益田さんのPCはIntel UHD Graphics(独立GPUなし)のため、画像生成AIはローカルで動かせない。
代わりに、Claude Code on the webのクラウド環境でBlender(PyPIの`bpy`)を動かし、
Claudeがプログラムで直接操作して描く。MCP連携やプラグインは不要。
(2026-11-21、クラウド環境で`bpy` 5.3による描画が約5秒/枚で動くことを確認済み)

1. **シナリオ・ネーム**: Claudeが話・コマ割り・構図・セリフを作る(`scenarios/`)
2. **キャラクター**: 益田さんの参考イラスト(`references/`)に合わせて、Claudeが
   Blender上で簡単な人型から作る(`characters/`)
3. **作画**: ポーズ・カメラ・背景をBlenderで組み、線画(Freestyle)とトーンで描き出す
4. **仕上げ**: 線の揺らぎ・強弱、効果線、トーン、吹き出し、写植をPythonの画像処理で入れる
5. **確認**: `drafts/` → 益田さん確認 → `review/` → 承認後 `published/`

## 「人間らしい作風」のための工夫
- 輪郭線を均一にせず、揺らぎと強弱、途切れを入れる
- 陰影はグラデーションにせず、少ない階調のトーンに分ける
- 3Dっぽい完璧なパースや左右対称を避け、少し崩す
- 写植には手書き風の無料フォントを使う

## フォルダ構成
- `references/`: 益田さんから受け取った参考イラスト(作風・キャラの見本)
- `characters/`: キャラクター設定(設定画・Blenderモデル・作成スクリプト)
- `scenarios/`: シナリオ・ネーム
- `drafts/` / `review/` / `published/`: 原稿の確認段階ごとの置き場
- `tools/`: 制作用スクリプト
  - `setup.sh`: 作業環境の準備(セッションの最初に実行)
  - `render_check.py`: 描画の動作確認
  - `generate_hf.py`: 画像生成AIで1枚生成する
  - `edit_qwen.py`: 見本画像を渡して、同じキャラを別のポーズ・表情で描かせる

## 注意事項
- 参考イラストは「作風・雰囲気の見本」として使う。既存の作品やキャラクターを
  そのまま再現・模写した原稿は作らない。
- クラウド環境は一時的なため、成果物は必ずこのリポジトリにコミットして残す。
- クラウド環境から一部サイト(blender.org等)にはアクセスできない。素材の追加が必要な
  場合は、益田さんにファイルを送ってもらう。

## 絵柄の決定(2026-11-22)
- 「AIイラストらしい顔(マスターピース顔)」を避けるため、品質タグ(masterpiece等)を外し、
  インク・手描き調の指示(B方式)で描く。ツヤ・なめらかな陰影・キラキラ・紙の写真風は除外する
  (比較結果: `characters/style_test_v1/_compare.jpg`)
- 椎菜・シロはB方式で決定。イヅルは益田さんがD方式(太い線・シンプルな陰影)を希望
  (B方式だとやや幼く見えるため)。作品全体の絵柄の統一感は、仕上げ処理で調整する
- 仕上げ処理 `tools/manga_finish.py` で、灰色のグラデーションを黒い線・ベタ・網点トーンに
  置き換える

## 作業ルール(2026-11-23、益田さん指定・必ず守る)
- **ログは必ず日本語で表示する。** 生成の進み具合・確認結果・エラーなど、益田さんに見せるログはすべて日本語にする
  (英語のまま出力されるツールのログは、日本語に言い換えてから見せる。監視スクリプトも日本語でログを書く)
