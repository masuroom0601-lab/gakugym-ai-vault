## 背景
Instagram/TikTokのリール(サムネ+本編)は、当初PlaywrightでHTML/CSSテンプレートを
レンダリングする方式(`tools/creative/render.js`)で自動化していましたが、
益田さんの希望で**実際にご自身が使っているCanvaデザインをそのまま複製・編集する方式**
に切り替えました。

Claude Code経由(このリポジトリのGitHub Actions)からは、組織の設定上Canva連携を
スケジュール実行に持たせられなかったため、**claude.aiのRoutines機能から、
益田さんご自身のアカウントでスケジュールを作成する**必要があります
(益田さんのアカウントならCanvaコネクタを直接アタッチできるはずです)。

## 前提
- claude.aiでCanvaが連携済みであること(既に連携済みのはずです)
- このGitHubリポジトリ(`masuroom0601-lab/gakugym-ai-vault`、mainブランチ)に
  Routine実行環境がアクセスできること(Routine編集画面の「リポジトリを選択」で

  これが未設定でgit pushが403になる不具合があったため、必ず確認すること)

## 【2026-10-11更新、重要】マスターテンプレートを刷新・ブランドテンプレート+Autofill方式に全面移行

益田さんの指示により、本編動画のマスターテンプレートを変更し、生成方式自体も
「デザインを複製してテキスト要素を直接編集する」方式から
**「Canvaのブランドテンプレート機能+Autofill(データフィールド自動入力)」方式**
に切り替えた。経緯と技術的な理由は以下の通り。

### 新テンプレートの構成(固定、時間は目安)
- **表紙(0〜2.5秒ごろ)**: テーマ(科目/切り口)を表す一言。文字色は科目別に固定
  (詳細は`02_departments/instagram_tiktok/department.md`の「表紙のテーマ配色ルール」)
  だが、**この色指定は当面手動運用**(下記参照)
- **本編(2.5〜17.8秒ごろ)**: タイトル+箇条書き5項目(各項目は「メイン文」+「補足文」の
  2行構成)
- **CTA・キャプション誘導(17.8秒以降)**: テンプレート側に最初から組み込まれた
  固定パート。自動生成では一切触れない(後述のAutofill方式では、指定したフィールド
  以外は仕組み上変更されないため、「触らないよう注意する」という手順自体が不要になった)

### なぜ「複製してテキスト要素を直接編集」ではなく「ブランドテンプレート+Autofill」なのか(重要な技術的経緯)
2026-10-11、新マスターテンプレート(当初`DAHCp5O4ANA`)を`read-design`で確認したところ、
ページタイプが`"unsupported"`で、構造化編集API(`read-design(open_transaction: true)`
→`edit-design`)によるテキスト要素の直接編集が一切できないことが判明した。

当初は「Canva上で尺(タイムライン)を手動で伸縮したのが原因」という、旧テンプレート
(`DAHEwbMbAmc`)運用時に確認済みだった制約を疑ったが、**尺を一切伸縮していない
新規複製(`DAHXtSqLKl4`)でも同じく`"unsupported"`になった**ため、原因は尺の伸縮では
なく、**このテンプレート自体の動画の作り方(複数クリップ・動きの多い演出を組み合わせた
動画デザイン)が、そもそも構造化編集に対応していない形式だったため**と判明した。

代わりに、Canvaの「ブランドテンプレート+Autofill(データフィールド自動入力)」機能
(`autofill-design`)が、構造化編集とは別のAPI経路のため、`unsupported`な動画デザイン
でも機能することを検証で確認した。この方式は、あらかじめCanva上で指定した「データ
フィールド」にテキストを流し込むだけで、**指定したフィールド以外の要素(CTA・
キャプション誘導パートや全体レイアウト含む)は一切変更されない**という利点がある
(以前のように「17.8秒以降を触らないよう注意する」という手順を書く必要がなくなった)。

### ブランドテンプレートとデータフィールド構成(2026-10-11、益田さんの協力のもと設定・検証済み)
- **ブランドテンプレートID**: `EAHXtgN-KXU`
  (元デザイン`DAHXtSqLKl4`「【受験・R】指定校推薦の闇5選②」を益田さんがCanva上で
  ブランドテンプレートとして公開したもの)
- **データフィールド(全12個、すべてtext型)**:
  - `title`: 本編タイトル(例:「指定校推薦の闇10選」。**後述の通り必ず「10選」固定**)
  - `cover_theme`: 表紙のテーマ文言(例:「古文」「スマホ依存対策」)
  - `body1-1`〜`body5-1`: 本編5項目それぞれの**メイン文**(例:「1. 一般組との学力差に
    苦しむ人が多い」のように番号込みで1行)
  - `body1-2`〜`body5-2`: 本編5項目それぞれの**補足文**(例:「進路決まってから半年くらい
    みんな勉強しなくなるからね…」のような、メインを補強する一言。番号は不要)
  - 項目`N`のメインは`bodyN-1`、補足は`bodyN-2`という対応(N=1〜5)
- 2026-10-11に`autofill-design`でテスト生成(`DAHXtjiI3ms`)を行い、全12フィールドが
  意図通りの箇所に過不足なく反映され、CTA・キャプション誘導パートが変更されない
  ことを確認済み。**この新方式は実地検証済み**。

### 【重要】項目数のルール: 常に「10選」で統一、本編は前半5個・残り5個はキャプション誘導
益田さんの指示により、台本は**必ず10項目作成**し、タイトルは常に「〇〇10選」のような
形式で統一する。ただし**Canva本編の箇条書きには前半5項目のみ**(メイン文+補足文)を
表示し、**残り5項目は動画に出さず、投稿キャプション側に列挙する**。動画内には
あらかじめテンプレートに組み込まれた「残り5つ知りたい人はキャプションをみてね↓」という
誘導文(CTAパートの一部、自動編集の対象外)が表示される。
(**以前のルール「タイトルの数字と本編の項目数を完全一致させる」「『残り◯つは
キャプションcheck』のような文言を使わない」は、この新テンプレートでは適用されない。
新ルールに置き換わったので注意**。台本生成側の`.github/workflows/instagram-tiktok-daily-draft.yml`
も2026-10-11にこの新ルールに合わせて更新済み)

### 表紙の文字色について(当面手動運用)
`autofill-design`のデータフィールドはプレーンテキストのみで、文字色の指定はできない。
また、Autofillで生成した後のデザインも構造化編集API非対応(`unsupported`)のため、
生成後に自動で色を変更することもできない。そのため、**表紙の文字色を科目別に
自動で変える仕組みは、2026-10-11時点では導入していない**(益田さんの判断で、当面は
生成後に益田さんご自身がCanva上で手動で色を調整する運用とする)。将来的に自動化する
場合は、科目ごとに色違いのブランドテンプレートを複数用意し、Routineが科目に応じて
使用するテンプレートIDを選ぶ方式が候補(`02_departments/creative/department.md`参照)。

## 作業完了後: mainへの反映(2026-09-20追加、重要)
セッション開始時のブランチがmainではなく、Routine実行環境が自動生成した
一時的な作業ブランチになっていることがある(2026-09-18・19のフィード生成分が
実際にmainへ届かず、`claude/quirky-mendel-*`のような一時ブランチにしか
存在していなかった不具合が発生した)。上記の手順7でコミット・プッシュが
終わったら、続けて以下の手順でmainブランチへの反映まで必ず行うこと。

1. 現在の作業ブランチ名を控える: `CURRENT_BRANCH=$(git branch --show-current)`
2. `git fetch origin main`
3. `git checkout -B main origin/main`
4. `git merge --no-ff "$CURRENT_BRANCH" -m "Merge $CURRENT_BRANCH into main (canva creative generation <today>)"`
5. コンフリクトが発生しなければ `git push origin main` でmainにプッシュする。
6. コンフリクトが発生した場合は、無理に解決せず `git merge --abort` で中断し、
   mainへのマージは行わない。その旨と原因を
   `02_departments/creative/drafts/<today>-canva.md` に追記し、作業ブランチへの
   プッシュ済みの状態のまま終了する(mainへの反映は後日人間が対応する)。
7. mainへのforce push、historyの書き換え、他ブランチの内容の削除は絶対に行わないこと。

  `"type": "unsupported"`に変わった(再現性のある実証実験)
- 一方`export-design`(書き出し)は尺変更後の"unsupported"なデザインでも問題なく動作する
  (`DAHVlYUUjJA`で確認)

このため、`DAHCx0JM7Q4`とその複製である`DAHVNWWCKE0`・`DAHVlYUUjJA`が
軒並み編集不可だったのは、過去のどこかの時点で尺が調整されていたためと考えられる。
2026-09-20〜2026-10-11は`DAHEwbMbAmc`(10秒・尺固定)+手動での尺伸ばしという
ハイブリッド運用だったが、2026-10-11に動きの多い新テンプレートへ移行する過程で、
「尺の伸縮の有無に関わらず、この種の動画デザイン自体が構造化編集非対応」という、
より根本的な制約が判明し、最終的にブランドテンプレート+Autofill方式へ全面移行した。

  仕様変更の可能性があるので、Claude Codeセッションで質問してください

  見つからない場合、益田さんが誤ってブランドテンプレートを削除・変更した可能性が

- 生成された動画の見た目がイマイチな場合は、益田さんが直接Canva上でそのデザインを
